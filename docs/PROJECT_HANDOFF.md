# Project Handoff

## Purpose

This repository powers two production applications:

1. The public Sword & Spirit Ministries website.
2. The internal admin application used to manage website content and operational records.

Both apps are React/Vite/Tailwind applications and are hosted on Firebase Hosting.

## Repository Layout

```text
/
├── admin/                 # Admin application
├── website/               # Public website
├── cloud-functions/       # Firebase Functions codebase
├── firebase/              # Firestore and Storage rules/indexes
├── scripts/               # Maintenance and backfill scripts
├── firebase.json          # Firebase hosting/rules/functions config
├── .firebaserc            # Firebase project and hosting targets
└── preview.json           # Local preview launcher config
```

The former `flutter-website/` source folder has been removed. Do not depend on it for new development.

## Deployment

From the repository root:

```bash
npx firebase-tools deploy --only hosting:admin,hosting:website
```

Current hosting URLs:

- Admin: `https://ssmi-admin.web.app`
- Website: `https://ssmi-web.web.app`

## Build Verification

Before deployment:

```bash
cd admin
npm run build

cd ../website
npm run build
```

The apps currently emit Vite chunk-size warnings. Those warnings are known and are not build failures.

## Data Flow

- Website visitors submit forms and view content through `website/`.
- Admin users manage content and records through `admin/`.
- Firestore is the shared data source between both apps.
- Firebase Authentication controls admin sign-in.
- Firestore/Storage security is controlled by files in `firebase/`.

## Important Shared Concepts

- Branch documents drive branch landing pages, branch contact pages, giving data, service times, and branch-specific content.
- Website-content documents drive homepage-level content such as latest sermon, year theme, and album release links.
- Event documents drive public event listings and registrations.
- Request/registration/sign-up/partner documents are generated by website forms and managed in admin.
- Admin tours are frontend-only and do not require Cloud Functions.

## Development Rules

- Keep public website UI changes visually consistent with the established SSMI styling.
- Reuse existing shared components before creating new ones.
- Avoid hard-coded branch contact/payment data when Firestore fields exist.
- Preserve route compatibility for deployed public pages.
- Run builds before deploys and before commits.
- Document new Firestore fields in the relevant README/developer guide.
